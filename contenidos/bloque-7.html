Bloque 7

Formularios

Los formularios son la forma en que el usuario envía datos al servidor: un registro, una búsqueda, una matrícula. HTML se encarga de recoger los datos y hacer una primera validación; procesarlos (guardarlos en una base de datos, por ejemplo) es tarea de un programa en el servidor.

7.1 El elemento <form>

Atributo Para qué sirve Valores
action URL del programa que recibe los datos. Si se omite, se envían a la misma página URL
method Cómo se envían get (por defecto) o post
target Dónde se muestra la respuesta _self, _blank
enctype Codificación. Para subir archivos hace falta multipart/form-data (con post) —
autocomplete Permite que el navegador sugiera valores guardados on, off
novalidate Desactiva la validación del navegador booleano

GET o POST

GET POST
Dónde viajan los datos En la URL: buscar?q=html&curso=1 En el cuerpo de la petición HTTP, no se ven en la URL
Se puede guardar en favoritos Sí No
Límite de tamaño Sí (unos miles de caracteres) Prácticamente no
Uso típico Búsquedas, filtros Registros, contraseñas, archivos, cualquier dato que cambie algo

Ojo: POST no cifra los datos; solo los oculta de la URL. La seguridad la da HTTPS.

7.2 Etiquetas: <label>

Cada control debe tener su label. Al hacer clic en el texto se activa el campo, y los lectores de pantalla lo leen. Dos formas de asociarlos:

id y name no son lo mismo: id une el campo con su label (y con CSS/JS); name es el nombre con el que el dato llega al servidor. Un campo sin name no se envía.

7.3 El elemento <input> y sus tipos

<input> es un elemento vacío cuyo comportamiento cambia con el atributo type:

type Qué muestra Notas
text Caja de texto de una línea Por defecto si no pones type
password Texto oculto con puntos No cifra nada, solo oculta
email Texto que debe tener formato de correo En móvil saca el teclado con @
tel Teléfono No valida el formato: usa pattern
url Dirección web Exige http:// o https://
number Número con flechas min, max, step
range Barra deslizante min, max, step, value
date Selector de fecha Valor en formato AAAA-MM-DD
time, datetime-local, month, week Hora, fecha y hora, mes, semana —
color Selector de color Valor en hexadecimal
checkbox Casilla de verificación: se pueden marcar varias checked para marcarla por defecto
radio Botón de opción: solo uno del grupo Todos los del grupo con el mismo name
file Seleccionar archivo accept, multiple; el form necesita enctype="multipart/form-data"
search Caja de búsqueda Muestra una × para borrar
hidden No se ve; envía un dato fijo Útil para identificadores
submit Botón que envía el formulario Mejor usar <button>
reset Botón que borra el formulario Usar con cuidado
button Botón sin acción (para JavaScript) —

7.4 Atributos de los campos

Atributo Para qué sirve Ejemplo
name Nombre del dato al enviarlo name="email"
value Valor inicial o valor enviado value="España"
placeholder Texto de ejemplo gris; desaparece al escribir. No sustituye al label placeholder="nombre@correo.es"
required Campo obligatorio required
readonly Se ve y se envía, pero no se puede modificar readonly
disabled Desactivado: no se puede usar ni se envía disabled
autofocus Recibe el cursor al cargar la página autofocus
size Ancho visible en caracteres size="30"
maxlength / minlength Longitud máxima / mínima del texto maxlength="9"
min / max / step Límites e incremento en números y fechas min="16" max="99"
pattern Expresión regular que debe cumplir pattern="[0-9]{5}"
multiple Varios valores (email, file) multiple
list Asocia un datalist de sugerencias list="ciudades"
autocomplete Pista para el autocompletado autocomplete="email"
form Asocia el campo a un formulario aunque esté fuera de él form="f1"

Patrones útiles (pattern):

Dato Patrón
Código postal [0-9]{5}
DNI [0-9]{8}[A-Za-z]
Móvil español [67][0-9]{8}
Solo letras [A-Za-záéíóúÁÉÍÓÚñÑ ]+

Añade title para explicar al usuario el formato que se espera: el navegador lo muestra en el mensaje de error.

7.5 Otros controles

Texto largo: <textarea>. Sí tiene etiqueta de cierre; el contenido entre ambas es el valor inicial.

Lista desplegable: <select> con <option> y, para agrupar, <optgroup>.

Atributos: multiple (elegir varios con Ctrl), size (filas visibles), selected en la opción por defecto.

Sugerencias: <datalist>. El usuario puede escribir libremente o elegir una sugerencia.

Botones: <button>. Mejor que input type="submit" porque puede contener texto con formato o imágenes.

Indica siempre type: dentro de un formulario, un button sin type actúa como submit.

Agrupar: <fieldset> y <legend>. Agrupan campos relacionados con un recuadro y un título. <fieldset disabled> desactiva todo el grupo.

Mostrar resultados: <output>, <progress> y <meter>: muestran un resultado calculado, una barra de progreso y una medida en un rango (por ejemplo, el nivel de la batería).

7.6 Validación en el navegador

Con required, type, min/max, minlength/maxlength y pattern el navegador no deja enviar el formulario hasta que todo es correcto, y muestra un mensaje. Es cómoda para el usuario, pero se puede saltar fácilmente (borrando el atributo en DevTools), así que el servidor siempre tiene que volver a validar. Pruébalo: borra un required con DevTools y envía.

7.7 Ejemplo completo

https://httpbin.org/post es un servicio de pruebas que devuelve los datos que le envías: así ves exactamente qué llega al servidor. Para GET usa https://httpbin.org/get.

7.8 Errores típicos

  • Campos sin name: no se envían.
  • radio con distinto name: se pueden marcar todos.
  • label for que no coincide con ningún id.
  • Usar placeholder en lugar de label.
  • Poner un form dentro de otro form.
  • Confiar en la validación del navegador como única seguridad.

Ejercicios del bloque 7

E25 Formulario de contacto

  1. En e25-contacto.html crea un formulario con nombre (text), correo (email), asunto y mensaje (textarea), y un botón de enviar. Cada campo con su label.
  2. Pon action="https://httpbin.org/get" y method="get". Envíalo y mira la URL: localiza cada name y su valor.
  3. Cambia a post y https://httpbin.org/post. Envíalo y busca los datos en DevTools › Red (Network) › la petición › Carga útil (Payload).
  4. Quita el name a un campo y comprueba que ya no se envía.

E26 Encuesta con todos los controles

En e26-encuesta.html crea una encuesta sobre hábitos tecnológicos que use: number (edad, de 16 a 99), date, range (satisfacción de 0 a 10), color (color favorito), tres checkbox, un grupo de tres radio, un select con dos optgroup y un campo con datalist. Envíala a httpbin y comprueba qué valor llega de cada control.

E27 Validación

  1. Añade a tu encuesta: required en los campos clave, pattern para un código postal y un DNI (con title explicativo), minlength en el nombre y un campo readonly con la fecha de hoy.
  2. Agrupa los campos en dos fieldset con su legend.
  3. Intenta enviar con datos erróneos y anota los mensajes del navegador.
  4. Borra un required con DevTools y envía: explica en un comentario por qué el servidor debe validar otra vez.

E28 Formulario de matrícula

Crea matricula.html para tu proyecto con tres fieldset (datos personales, datos académicos y módulos en los que se matricula, con checkbox), subida de foto (file con accept="image/*"), aceptación de condiciones obligatoria y botones de enviar y borrar. Debe validar sin errores.
